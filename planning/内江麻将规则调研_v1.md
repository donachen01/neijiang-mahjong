# 内江麻将规则调研 v1

更新时间：2026-04-30  
用途：作为“内江麻将工程”第一版规则梳理文档，用于后续程序规则落地。  
说明：目前网上能查到的公开资料较分散，且存在平台版本差异；以下内容是**交叉归纳后的候选标准版**，不是官方唯一口径，正式开发前仍建议你逐条确认。

---

## 1. 当前能较稳定确认的规则骨架

### 1.1 用牌
- 使用两门牌：`条`、`筒`
- 不使用：`万`、风牌、箭牌、花牌
- 总牌数：`72 张`

### 1.2 基本玩法
- 四人对局
- 庄家起手 `14 张`，闲家起手 `13 张`
- 玩法偏四川系简化麻将
- 只能 `碰`、`杠`，`不能吃`

### 1.3 局制特征
- 搜到的资料普遍指向：**内江麻将属于“推倒胡 + 血战”体系的地方变体**
- 也就是说，它并不只是普通推倒胡，而是带有四川麻将那种持续作战、结算偏本地化的味道

### 1.4 胡牌方式
- 支持 `自摸`
- 支持 `点炮`
- 支持 `抢杠胡`
- 支持 `杠上花`
- 支持 `杠上炮`
- 支持 `海底`

### 1.5 过水规则
- 已检索到明确表述：`同一圈内，不能不胡前面胡后面的，但自摸可以胡`
- 这意味着：如果同一轮你放弃了可胡的放炮牌，后面同轮再遇到同类放炮，通常不能再胡；但如果自己摸到，则仍可自摸

### 1.6 荒庄后处理
- 存在 `查叫`
- 现有资料倾向于：`黄庄后按点炮查，查大的`

### 1.7 杠分 / 雨钱 / 退税
- 已检索到较一致的本地说法：
  - `巴杠 / 补杠`：每家付 `1 倍底`
  - `直杠 / 明杠`：点杠者付 `2 倍底`
  - `暗杠`：每家付 `2 倍底`
- 存在 `杠牌者没叫则退税` 的规则
- 抢杠胡、杠上炮还涉及 `杠分转移`

## 2. 已检索到的番型信息

> 下面这部分主要来自公开玩法介绍，可信度“中等”，适合作为首版候选实现，但建议你再按你熟悉的本地玩法复核。

### 2.1 常见番型与番数（候选版）
- `卡二条`：1 番
- `报叫`：1 番
- `归`：1 番
- `杠上花`：1 番
- `抢杠胡`：1 番
- `杠上炮`：1 番
- `海底`：1 番
- `大对子`：3 番
- `清一色`：2 番
- `暗七对`：2 番
- `地胡`：+4 番，定义为闲家首轮胡庄家第一张出牌，当前项目按 5 番封顶
- `天和`：+4 番，当前项目按 5 番封顶
- `龙七对`：3 番
- `清对`：3 番
- `清七对`：3 番
- `青龙七对`：4 番

当前项目分值折算表：
- `1 番 = 1 分`
- `2 番 = 2 分`
- `3 番 = 4 分`
- `4 番 = 8 分`
- `5 番及以上 = 16 分`

### 2.2 自摸加成
- 当前项目口径：`自摸额外 +1 分`
- 自摸不作为翻倍项处理；5 番封顶只封基础胡牌番值，不截断这 1 分附加

## 3. 需要重点确认的“内江麻将特色项”

这些点决定了程序实现方式，建议你后面直接拍板：

### 3.1 是否保留“血战到底”
网上材料出现两种表述：
- 一类说法把它描述为“推倒胡 + 血战”核心
- 另一类规则介绍更像是“有人胡就按本地结算继续/结束”的简版

**开发建议**：这一条必须先定。  
因为如果是血战：
- 胡牌玩家离场/留场逻辑不同
- 摸牌顺序、查叫、剩余玩家继续对局都不同
- 结算页结构也不同

### 3.2 “报叫”是否为强制锁手
已检索到表述：
- 起手听牌可 `报叫`
- 报叫后 `不能换牌`
- 报叫后如有自摸或放铳，系统自动和牌
- 庄家 `不可以报叫`
- 报叫后若别人胡了，报叫的人也要 `多输一番`

这是一条很有辨识度的本地规则。  
如果保留，AI 与交互都要单独做：
- 报叫按钮
- 报叫状态 UI
- 报叫后的自动出牌/锁牌
- 报叫附加输分

### 3.3 “卡二条”到底如何判定
公开资料只有一句高度口语化描述：
- `卡二条：即和 2 条嵌单，只要能摆出来卡 2 条就行，1 番`

但程序实现时至少要明确：
- 是否限定胡 `2 条`
- 是否必须是 `1-3 条` 中张嵌张成和
- 是否要求“最终胡牌牌型里存在一组卡 2 条”即可
- 七对、自摸、杠后胡时是否还能同时算卡二条

### 3.4 七对是否允许明牌后成立
需要确认：
- `暗七对` 是否要求全门清
- 碰过/杠过后是否一律不能算七对
- `龙七对 / 青龙七对` 与 `归` 是否叠算

### 3.5 番型是否叠加、是否封顶
目前公开资料能看出番数列表，但没有清晰说明：
- 是否完全累加
- 是否存在封顶番数
- 是否有互斥关系（如清对是否包含清一色+大对子、是否只记高不记低）

程序里这会直接影响 `fan_resolver` 的实现方式。

### 3.6 一炮多响 / 多家可胡
当前公开资料里没有拿到特别稳的统一表述。  
如果是四川地方系玩法，往往存在多家同时胡牌的可能；但内江本地版本是否保留，需要你确认。

### 3.7 庄家轮转
需要确认：
- 胡牌坐庄？
- 庄家胡了连庄？
- 荒庄庄家是否继续？
- 血战模式下本局庄家影响是否只在开局/首胡阶段有效？

## 4. 面向程序实现的“首版候选规则”

如果要让我先做一个**能跑的内江麻将 alpha 版**，我建议先按下面这版落地：

### 4.1 推荐首版规则骨架
- 四人麻将
- 72 张牌（条、筒）
- 不能吃，只能碰、杠、胡
- 支持自摸、点炮、抢杠胡、杠上花、杠上炮、海底
- 保留查叫
- 保留杠分、退税、杠分转移
- 保留报叫
- 保留卡二条
- 番型先按现有公开列表实现

### 4.2 推荐首版结算骨架
- 先做“番型累加”模式
- 默认不设高封顶，待你确认后再收口
- 杠分独立结算
- 自摸增加一档基础收益
- 查叫按公开资料先做“按点炮查大叫”

### 4.3 推荐首版 AI 取向
内江麻将因为只有两门牌，牌效率和读牌速度会明显快于四川血战三门麻将，因此 AI 应更偏：
- 快速成叫
- 控制过水
- 追踪 2 条相关结构
- 强化对报叫状态玩家的防守
- 明确区分：做大牌 vs 先下叫

## 5. 对现有四川麻将工程的改造影响

和当前四川麻将项目相比，内江麻将至少有以下结构性变化：

### 5.1 牌库层
- 去掉 `万` 牌
- 去掉字牌
- 去掉定缺逻辑
- 所有牌效率、可见张、胡牌概率重新计算

### 5.2 规则层
- `rule_config.gd` 需要新增内江玩法配置
- `hu_checker.gd` 需要加入报叫 / 卡二条 / 七对限制等判定
- `fan_resolver.gd` 需要改成本地番型表
- `score_resolver.gd` 需要支持雨钱、退税、查叫、杠分转移

### 5.3 AI 层
- 现有四川麻将 AI 里大量“定缺 / 三门竞争 / 清缺门优先”逻辑要删掉或禁用
- 新 AI 要改为：
  - 两门牌速度型计算
  - 听牌优先
  - 报叫约束
  - 卡二条价值评估
  - 过水风险控制

### 5.4 UI 层
- 去掉定缺按钮和定缺语音
- 结算页番型文案改为内江版
- AI 辅助文案要从“四川血战逻辑”改为“两门快节奏逻辑”

## 6. 当前结论

### 6.1 我认为“比较靠谱”的核心判断
基于目前公开资料，**内江麻将大概率不是把四川麻将简单换皮**，而是：
- 两门牌简化牌库
- 碰杠胡为主，不吃
- 带明显地方特色番型（尤其是 `卡二条`、`报叫`、`归`）
- 结算上保留四川系的杠分、查叫、抢杠、杠转移味道
- 节奏比现有四川麻将工程更快

### 6.2 我建议的开发策略
不要直接在当前四川规则上硬改。  
建议在新工程里：
1. 先抽离 `四川专属规则`
2. 新建 `内江规则配置 + 判定器`
3. 先实现“能跑的首版候选规则”
4. 再根据你的本地经验逐条修正
