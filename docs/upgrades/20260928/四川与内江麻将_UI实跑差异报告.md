# 四川麻将与内江麻将 UI 实跑差异报告

日期：2026-09-28。对照对象是当前工作区内江麻将和 `/Volumes/AI/Codex/四川麻将工程_20260701_v2` 的四川麻将。两者均由 Godot 4.6.2 在 macOS Metal/OpenGL 兼容渲染下实际加载界面，按 2560×1440 截图。四川牌桌、工具栏、动作与桌布页显式选用 `blue_glass`；内江使用当前蓝玻璃皮肤。十组原尺寸截图保存在 `evidence/ui_compare_20260928/`。

## 需要优先处理的具体问题

1. **行牌中无法从内江工具栏查看对局详情。** `scripts/ui/table/NeijiangUtilityBar.gd` 只在 `current_phase == 7` 显示“结算”“下一局”；`scripts/game/MainSceneV2.gd` 的 `_on_top_settlement_info_pressed()` 也在非结束阶段直接返回。四川工具栏有持续可见的“对局详情”，可查看排行、流水和规则。内江应增加独立的“对局详情”入口，允许进行中只读查看，退出详情后回到原牌局；“下一局”仍只在结算阶段出现。对局信息必须采用真实历史与房间规则。
2. **四页结算尚属旧界面内嵌页签。** 内江当前 `scripts/game/MainSceneV2.gd` 使用旧结算容器，加了页签和逐行说明；四川是统一玻璃页面加结构化卡片／表格。建议先迁移共用外壳与页签，再分别整理：当前局四家卡片及结算明细、排行表和概览、流水表与空状态、按内江规则分组的规则状态。保留内江独有手牌与计分细节，避免照抄四川“缺门”“花猪”等文案。
3. **蓝玻璃结算皮肤存在资源路径错误。** 内江 `scripts/game/MainSceneV2.gd` 的 `_refresh_settlement_skin_palette()` 请求 `res://res/art/materials/table_skins/blue_glass/albedo_2k.jpg`；现有资源是 `albedo_2k.png`。实跑结算日志出现“Resource file not found”，说明结算调色纹理未正确载入。应从皮肤清单读取实际文件名，并用实跑日志确认不再报错。
4. **展开工具栏遮挡牌桌，且样式与蓝玻璃系统脱节。** 内江目前是两列大实体按钮并覆盖左侧座位与牌墙；四川抽屉用轻量背景和较紧凑的行。应在保留“调参”“旧版UI”等内江专有功能的前提下压缩行高、统一图标和文字状态、让面板避开玩家信息；增加“对局详情”后尤其需要重新测量宽高、窄屏安全区和触控目标。

## 建议验收顺序

先修结算皮肤路径，再打通进行中只读“对局详情”；随后统一四页结算外壳及内容布局，最后调整工具栏与 HUD 细节。每一阶段均以蓝玻璃、普通桌布各拍一组 2560×1440 桌面图；结算排行／流水要分别使用空历史和至少三局真实格式的非空历史，检查列宽、滚动、正负分、高亮与关闭返回。窄屏手机横屏、安全区、声音试听实际点击、真机渲染与联机房间内的对局详情仍需单独验收，桌面截图不能代替这些结果。
