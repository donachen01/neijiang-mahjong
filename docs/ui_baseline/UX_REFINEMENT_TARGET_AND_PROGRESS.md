# 内江麻将主牌桌 UX/UI 精修目标与进度跟踪

> 状态：执行中  
> 首版日期：2026-05-11  
> 当前版本：1.0.14
> 目标界面：主牌桌对局界面  
> 设计方向：3D 卡通轻奢质感 Mahjong UI  
> 执行原则：保留已校准布局，逐步资产化和统一视觉系统，每次版本更新后检查目标完成度并继续推进未完成任务。

## 1. 项目目标

将当前内江麻将主牌桌从原型级绿色牌桌，升级为与启动界面同源的「3D 卡通轻奢质感麻将对局界面」。本目标不是重新排版，不重新设计玩法，也不改变当前已经反复校准的手牌区、碰杠区、胡牌区、弃牌区、玩家信息框和按钮的大体位置。后续工作应在保留布局合同和交互逻辑的前提下，持续提升视觉统一性、牌面资产质量、桌面材质、HUD 规范、可读性和移动端可用性，直到目标完成度达到 100%。

最终界面应满足以下描述：

- 全局共用一张连续的深绿色绒面麻将桌基底，手牌区、碰杠区、胡牌区、中央弃牌区不再依赖独立底色、区域框线或分割板表达层级。
- 所有麻将牌像真实摆在桌面上，靠圆角厚度、绿色侧边、接触阴影、统一高光和空间层级区分，而不是靠粗描边和分区背景。
- 自家手牌是第一视觉层级，动作按钮和 AI 推荐是第二视觉层级，最近出牌/胡牌来源/玩家状态是第三视觉层级。
- 主牌桌 HUD 必须克制、贴边、可读，不把大量说明卡、调试入口或旧式信息面板放在中心牌桌上。
- 美术语言与启动界面一致：温润、圆润、柔和光影、玩具级 3D 卡通质感、轻奢但不赌场化、不后台工具化。

## 2. 约束条件

- 不改变麻将规则、AI 策略、出牌流程、结算逻辑、存档行为。
- 不重新打乱已经调好的桌面几何关系；布局变更必须有明确问题依据并通过 `tests/V17LayoutContract.gd`。
- 保留现有麻将牌数量、玩家方位、操作入口、胡牌来源、AI 出牌提示等功能。
- 所有主牌桌视觉改动必须截图验证，至少覆盖 `2048x1152` 横屏主视图。
- 每次有意义的代码、资产、文档、版本变更必须提交到 Git，并在需要时同步版本号。
- Android 导出相关版本应同步更新 `export_presets.cfg` 的 `version/name` 与 `version/code`。

## 3. 可衡量验收标准

| 维度 | 目标标准 | 当前完成度 |
|---|---|---:|
| 布局稳定性 | 现有四家牌区、碰杠、胡牌、弃牌、按钮位置不被破坏，布局合同测试通过 | 85% |
| 桌面统一性 | 无明显分区底色/边框；桌面有连续绒布纹理、中心光、暗角，但无抢眼装饰线 | 72% |
| 麻将牌本体 | 厚牌圆角、暖象牙牌面、绿色侧边、统一投影；正背面同一资产体系 | 73% |
| 正面牌纹 | 条、筒、万、幺鸡等符号与新牌底同风格，线条柔和清晰，不像旧贴图 | 64% |
| 牌背 | 素玉牌背与桌面有足够分离度，无旧圈纹，阴影统一 | 76% |
| 玩家信息 HUD | 贴边、清晰、弱面板化；字体、头像/定缺、分数、已胡状态统一 | 62% |
| 操作按钮 | 右上/动作按钮采用同系列 3D 果冻/玉石按钮，触控目标清晰 | 64% |
| AI 提示 | 提示框居中、大字、只显示内容；推荐牌用悬浮 3D 标记，不遮挡读牌 | 74% |
| 可访问性 | 手机横屏玩家名/分数/状态可读；关键文字对比度足够，不仅靠颜色表达状态 | 69% |
| 启动图一致性 | 整体材质、光照、圆润度、颜色气质接近启动界面 | 60% |

当前综合完成度：约 75%。
达到 100% 的判定：上表所有维度均不低于 90%，且用户截图评审确认「整体接近预期效果」。

## 4. 执行步骤

### 步骤 1：锁定目标模板与验收基线

行动要点：

- 选定当前主桌面布局作为几何基准，不再随意改变牌区位置。
- 保存每轮 `2048x1152` 主桌面截图作为对照。
- 在本文件维护完成度矩阵，并在每次版本更新后修正。

预期产出：

- `docs/ui_baseline/UX_REFINEMENT_TARGET_AND_PROGRESS.md`
- 最新主桌面截图路径记录
- 每轮版本号、提交号、完成度记录

### 步骤 2：重做麻将牌正面资产

行动要点：

- 优先重做本家手牌 14 张可见牌所需的条、筒、万、幺鸡正面符号。
- 将旧牌面符号从“硬贴图”转为与厚玉牌底一致的柔和 3D 卡通符号。
- 保持当前手牌尺寸、点击区域和布局合同不变，只替换/优化视觉资产。

预期产出：

- 新版透明底牌面符号资产
- 自家手牌不再像白色方块，牌面、侧边、投影明确
- 桌面小牌和自家大牌视觉体系一致

### 步骤 3：统一麻将牌光源和材质规则

行动要点：

- 统一左上高光、右下暗部、底部接触阴影。
- 去掉脏黑硬边和不一致描边。
- 牌背与桌面绿色拉开明度和饱和度，保证远景可辨认。

预期产出：

- `HandCanvas2D.gd` 与 `TileVisual2D.gd` 共用同一套材质方向
- 牌背、牌面、弃牌、碰杠牌的厚度和阴影风格一致

### 步骤 4：重构玩家信息 HUD

行动要点：

- 弱化半透明绿框和金色旧边框。
- 玩家信息改为轻玻璃/玉牌式贴边 HUD，突出定缺、姓名、分数、已胡状态。
- 增大手机横屏下的关键文字可读性。

预期产出：

- 玩家信息卡不再像旧式面板
- 四家信息统一，且不抢中心牌局

### 步骤 5：统一按钮与辅助入口

行动要点：

- 右上角按钮改为同系列 3D 圆润按钮，区分主次。
- 操作按钮保持大触控目标，弱化旧式矩形按钮。
- 调试/辅助入口收纳为低干扰图标，不抢正常牌局。

预期产出：

- 按钮系统与牌桌材质统一
- 关键操作路径更直观，认知负荷更低

### 步骤 6：打磨桌面材质与中心留白

行动要点：

- 强化绒布细节、中心聚光、边缘暗角。
- 移除像边框的装饰线，保留连续桌面质感。
- 中心留白要显得高级、干净、有材质，不显得空。

预期产出：

- 桌面不再像纯绿色底板
- 无多余分区色块和边框干扰

### 步骤 7：可访问性与移动端检查

行动要点：

- 检查玩家名、分数、按钮、AI 提示在手机横屏上的字号和对比度。
- 推荐、危险、选中、胡牌来源不能只依赖颜色，必须有形状/动效/位置辅助。
- 用 `2048x1152` 和 `1365x768` 做截图检查。

预期产出：

- 关键文字不糊、不小、不溢出
- 操作入口触控目标清晰

### 步骤 8：版本更新闭环

行动要点：

- 每完成一个可评审版本，运行布局合同测试并截图。
- 更新本文件的完成度表和版本记录。
- 若完成度未到 100%，按未完成维度继续拆任务执行。
- 提交代码、资产、文档和版本号，推送 GitHub。

预期产出：

- 每版都有提交号、版本号、测试结果、完成度变化和下一步任务。
- 目标完成前不停止在“方向差不多”的中间状态。

## 7. 完成定义

当以下条件全部满足时，本目标可标记为 100%：

- 用户确认截图整体接近预期的 3D 卡通轻奢风格。
- 布局合同测试通过。
- 主牌桌截图中无明显分区底色、区域框线或旧式面板割裂感。
- 麻将牌正背面形成统一资产体系，边角、厚度、光影、牌纹均稳定。
- 玩家信息、按钮、AI 提示、胡牌来源标记属于同一 HUD 语言。
- `2048x1152` 与 `1365x768` 下关键牌面、文字、按钮均可读可点。
- 版本号、文档进度、Git 提交、GitHub 推送均完成。
